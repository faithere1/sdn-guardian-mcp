### Design choices that matter in Colab

- **Server stderr goes to a file** (`/tmp/sdn_guardian_server.log`). The MCP stdio client
  passes `sys.stderr` to the subprocess by default, and Jupyter's stderr has no real file
  descriptor. The `guardian_client()` helper calls `stdio_client(params, errlog=<file>)`
  and passes that transport to `mcp.Client`.
- **`src/` is added to `sys.path`** in the install cell, so the package imports without a
  kernel restart.
- **`server_env()`** puts the package on the server subprocess's `PYTHONPATH`, because the
  default stdio env drops it.
- **Mock DB** at `/content/sdn_guardian_mock.db`. Live mode uses a separate
  `/content/sdn_guardian_live.db`, so the two never mix.
- **`HF_TOKEN`** comes from Colab Secrets (`google.colab.userdata`) and is never printed. The
  settings cell prints only `SDN_GUARDIAN_*` / `IOSXE_*` variables.

## 2. Getting the code into Colab

The project had no GitHub remote yet, so the zip-upload path was used:

1. On the Mac, zip the project without local artifacts:
   ```bash
   cd sdn-guardian-mcp
   zip -r ~/Desktop/sdn-guardian-mcp.zip . -x ".venv/*" "*__pycache__*" "*.egg-info/*" "*.db" ".env"
   ```
2. In Colab, choose **File → Upload notebook** and upload the `.ipynb`.
3. Upload `sdn-guardian-mcp.zip` to `/content/` via the Files panel.
4. Add a cell at the top and run:
   ```python
   !unzip -q -o /content/sdn-guardian-mcp.zip -d /content/sdn-guardian-mcp
   ```
   The install cell skips `git clone` when `/content/sdn-guardian-mcp` already exists.
5. Add `HF_TOKEN` (a Read token) in Colab Secrets and turn on **Notebook access**. Accept the
   model's terms on Hugging Face if asked.
6. Set **Runtime → Change runtime type → GPU**.

After a runtime reset, uploaded files are gone, so steps 3–4 have to be repeated. Once the
repo is on GitHub (Phase 9), set `REPO_URL` and the clone path works without a zip.

## 3. Problem found: `ModuleNotFoundError: No module named 'mcp'`

**Symptom:** the "MCP client helper" cell failed at `from mcp import Client`.

**Cause:** the project's dependencies were not installed in the kernel's Python. The install
cell runs `pip install -q`, and `-q` hides pip's output, so it was not visible whether pip
failed or whether the cell had not run.

**Diagnosis / fix:** run the install again with its output visible, then check the import:
```python
import sys
!{sys.executable} -m pip install -e "/content/sdn-guardian-mcp[llm,live]" 2>&1 | tail -25
!{sys.executable} -c "import mcp; print('mcp OK:', mcp.__file__)"
```
Then restart the session (**Runtime → Restart session**) and rerun from the install cell.
The user fixed it by adding a separate `!pip install -q mcp` cell after the install cell.
After that, the "Tools: [...]" line printed. Why the editable install did not bring in `mcp` is
unknown. The install cell now installs `mcp>=2.3,<3` explicitly after the editable install.

**Follow-up (Phase 9):** make the install cell show pip errors: drop `-q`, or capture the
output and print its tail if pip fails. The user's fixed notebook replaces the generated one
(see §5).

### §2: the real model's trace

1. `get_traffic_anomalies(window_s=60)`: CRITICAL SYN_FLOOD 10.10.20.45 on
   GigabitEthernet0/2 → 10.10.10.10 tcp/443.
2. `detect_network_drift(interface='GigabitEthernet0/2')`: vlan SoT 20, live 99.
3. `simulate_flow_impact(src 10.10.20.45/32 → 10.10.10.10/32 tcp/443, deny, prio 100)`:
   **FAIL**, SHADOWED by #10 prio 100. Fix: "Minimum safe priority: 101".
4. Same rule at prio 101: **PASS** (GENERALIZATION info).
5. `push_safe_sdn_policy(simulation_id=..., timeout_s=300)`: PENDING.
6. `confirm_commit(commit_id=...)`: **COMMITTED**, health check passed.

**Observations:**
- **Valid JSON every turn.** The model never needed a parse retry, and it carried the
  simulation and commit IDs forward correctly.
- **It followed the server's fix exactly** (101, the minimum safe priority).
- **Narrower rule than the replay agent.** The model blocked only `tcp/443 → controller`; the
  replay agent blocks `any → any` from the attacker. Both are valid, but the narrow rule
  leaves other ports and hosts open to the attacker.
- **`timeout_s=300`** (5 min) instead of the 30 s default. The server accepted it, because
  there is no upper limit on `timeout_s` today.

### §3: replay agent (reference)

Rule: `DENY any 10.10.20.45/32 -> 0.0.0.0/0`.
